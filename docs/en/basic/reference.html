BASIC reference

This page describes every statement, function and operator of ZX-V BASIC, plus the error messages, the character set and the limits of the machine. It is a reference: to learn the language step by step, start with the BASIC course; to learn how to type and change programs, read the editor.

How to read this reference#

Each statement and each function has an entry with the same parts, always in this order:

  1. Syntax, in a box:

PRINT [AT row, column;] [item] [; item]...

  1. What it does, in one or two sentences, with anything that may surprise you.
  2. Parameters: a table with each value you supply, the values it takes (ranges, units, special values, the one used if you leave it out) and what it is.
  3. Returns (functions only): the value they give and what it means.
  4. Errors: a table with the reports it can give and when. The (common) row points to the errors any statement can give, which are not repeated in each entry.
  5. Example: a few lines you can type as they are.
  6. See also: the related entries.

The entries that explain an idea and are not a statement (Numbers, Strings, Variables...) do not have these parts: they are an explanation.

In the syntax:

  • Words in UPPER CASE are keywords: type them as they are (in upper or lower case, it makes no difference).
  • Words in lower case are things you supply: n, x, row are numbers or numeric expressions; names ending in $ (a$, name$) are strings; line is a line number; var is a variable name.
  • [ ] mark an optional part; ... means the part before can be repeated; | separates alternatives (IN | OUT means "IN or OUT").
  • Punctuation such as ,, ;, ( and # is typed exactly as shown.

When something goes wrong, the machine gives an error report, written here as its code and message, for example B Integer out of range (see Error messages).

A statement (also called a command) does something: PRINT, GO TO, BEEP. A function gives back a value and is used inside expressions: SQR 16, LEN a$, INKEY$. Most statements can be typed either in a program line (with a line number, to be run later) or as a direct command (without a number, run as soon as you press Enter).

If you know the Spectrum: ZX-V BASIC runs Sinclair BASIC programs from the 48K, plus PLAY from the 128K, and adds many extensions (structured loops, procedures, labels, error trapping, sprites, files...). Keywords are typed letter by letter, as on the 128K, not with single keys.

The language#

Program lines and statements#

A program is a list of lines. Each line starts with a line number from 1 to 9999; the lines are kept in order of their numbers, whatever order you type them in. A line can hold several statements separated by colons (:):

10 PRINT "Hello": PRINT "again"
20 GO TO 10

Line numbers usually go in tens (10, 20, 30...) so there is room to add lines in between later; RENUM tidies them up again. A line typed without a number is a direct command and runs at once.

When you press Enter, the editor checks the line. If it is not valid BASIC, it neither stores nor runs it: the status line says what is wrong (nearly always C Nonsense in BASIC) and the cursor stays where the fault is. So most typing mistakes show up as you type, not when the program runs.

When something goes wrong while running, the error report says where: 2 Variable not found, 20:1 means statement 1 of line 20 (see Reports).

Numbers#

Numbers are written as 42, 3.25, .5 (with a point, not a comma) or in scientific notation: 1E6 is 1 000 000 and 2.5E-3 is 0.0025 (-7 is the number 7 with the minus sign in front). They go from about ±2.9E-39 to ±1.7E38; a larger result gives 6 Number too big, and a smaller one becomes 0. BIN writes a number in binary.

PRINT shows up to 8 significant digits, rounded and without trailing zeros. It switches to scientific notation when there are 9 or more digits before the point, or more than 4 zeros after it; numbers between 0 and 1 with a zero after the point are written without the leading 0:

PRINT 1/3, 2^31, 1E10, 0.000001, 0.05

shows 0.33333333, 2.1474836E+9, 1E+10, 1E-6 and .05.

Inside, numbers have more precision than on the Spectrum, but comparisons (=, <, >...) are done with the same precision as the Spectrum, so 0.1*3=0.3 is true.

Strings#

A string is a piece of text between double quotes: "Hello". To put a quote inside a string, write it twice: PRINT "say ""hi""" shows say "hi". The empty string is "". A string can be as long as memory allows.

+ joins strings: "ZX" + "-V" is "ZX-V".

A slice is part of a string. Character positions start at 1:

Expression Result Meaning
"hello"(2 TO 3) "el" characters 2 to 3
"hello"(3) "l" character 3
"hello"(TO 2) "he" from the start to 2
"hello"(3 TO) "llo" from 3 to the end

A slice that starts after it ends is the empty string ("hello"(3 TO 2) is "", with no error); otherwise a position outside the string (0 too) gives 3 Subscript wrong, and one greater than 65535 or negative, B Integer out of range. Slices work on string variables, on strings written in the program and on any expression in brackets: (a$+b$)(2 TO). You can also assign to a slice: LET a$(1)="J" changes the first character (without changing the length of a$).

Strings are compared character by character using their codes (see Character set), so "B"<"a" is true, and "ab"<"abc" too.

Variables#

A variable holds a value under a name.

  • Numeric variables have names made of letters and digits, starting with a letter: x, score, level2. Names can be long (up to 63 characters), upper and lower case are the same (Score and SCORE are one variable), and spaces inside the name are ignored (my score is myscore). They do not take accented letters or ñ (if you type them, they are written without the accent: número becomes numero).
  • String variables have a single letter followed by $: a$, n$. There are 26 of them.
  • The control variable of FOR is a single letter, and it is an ordinary numeric variable: FOR i uses (and changes) any i there was.
  • A name cannot be a Spectrum keyword or a ZX-V function: LET print=1 and LET time=1 are errors. ZX-V's own statements (MODE, WHILE, SPRITE...) are only recognised at the start of a statement, so they are fine as names (LET mode=1), so as not to break old programs. A keyword inside a longer name is fine (total, ink2).

A variable is created the first time it is given a value (with LET, INPUT, READ, FOR, or as a parameter of a procedure). Reading a variable that does not exist gives 2 Variable not found. RUN and CLEAR delete all the variables.

10 LET my score=10
20 LET a$="Ann"
30 PRINT a$; " has "; MyScore; " points"

Arrays#

An array is a numbered list of values (or a table, with several dimensions). It has a single-letter name and is created with DIM:

10 DIM t(5): DIM g(3,3)
20 LET t(1)=100: LET g(2,3)=7
30 PRINT t(1); " "; g(2,3); " "; t(5)

Subscripts start at 1. Numeric arrays start full of zeros. A numeric array and a numeric variable can share a letter (a and a(1) are different). A string array a$ replaces the string variable a$. A subscript outside its dimension, or a number of subscripts that is not the array's, gives 3 Subscript wrong; using an array before its DIM, 2 Variable not found.

String arrays are arrays of characters: the last dimension is the fixed length of each string. DIM n$(3,10) makes 3 strings of 10 characters, filled with spaces. n$(2) is the second string, and n$(2,1) its first character. Assigning a shorter text fills the rest with spaces; a longer one is cut:

10 DIM n$(2,4)
20 LET n$(1)="good morning"
30 PRINT n$(1); "|"; n$(2); "|"

shows good| |. n$ without subscripts is the whole array as a single string (here, of 8 characters), and LET n$="..." fills it from start to end in the same way, without changing its size.

Expressions and operators#

An expression combines values with operators. When there are several operators, the ones with higher priority are worked out first:

Priority Operators Meaning
highest functions SIN x, LEN a$... take only the value right after them
10 ^ power
9 - (in front) change of sign
8 * / multiplication, division
6 + - addition (and joining strings), subtraction
5 = < > <= >= <> comparisons
4 NOT logical not
3 AND logical and
lowest OR logical or

Operators with the same priority are worked out from left to right, so 2^3^2 is (2^3)^2 = 64. Change of sign goes after the power: -2^2 is -4. Brackets change the order: (1+2)*3 is 9. A + in front of a number is allowed and does nothing.

Functions take only the value that follows them: SQR 16+9 is (SQR 16)+9 = 13, and SQR (16+9) is 5. When in doubt, use brackets.

Both sides of an operator must be of the same type (two numbers or two strings); otherwise, C Nonsense in BASIC. With strings only +, the comparisons and AND (with a number on the right) are allowed.

Dividing by zero gives 6 Number too big, and so does raising 0 to a negative number. Raising a negative number to a power gives A Invalid argument, even if the power is whole ((-2)^2); 0^0 is 1.

True and false#

Comparisons give 1 when true and 0 when false: PRINT 3>2 shows 1. IF, WHILE and UNTIL take any number: 0 is false and anything else is true.

Expression Value
NOT x 1 if x is 0, otherwise 0
x AND y x if y is not 0, otherwise 0
x OR y 1 if y is not 0, otherwise x
a$ AND y a$ if y is not 0, otherwise ""

So IF a>0 AND a<10 THEN ... works as you expect, and a trick like PRINT ("valid" AND ok); ("not valid" AND NOT ok) prints one thing or the other.

Whole-number arguments#

Many statements need whole numbers (a line number, a colour, a coordinate). If you give a number with decimals it is rounded to the nearest whole number, with halves going up: 2.5 becomes 3 and -2.5 becomes -2. A value between -0.5 and 0 counts as 0.

Nearly all of them first read the number with a wide range, the one for its type: 0 to 255 for colours, rows and columns; 0 to 65535 for line numbers and times. A negative value or one above that maximum always gives B Integer out of range. Then each statement checks its own range, and there the report may be a different one. For example, with INK (which takes 0 to 9):

Statement Report Why
INK 10 K Invalid colour Between 0 and 255, but not a colour.
INK 300 B Integer out of range Greater than 255.
INK -1 B Integer out of range Negative.

Each entry gives both ranges and which report each one gives.

Errors in any statement#

These reports can come from almost any statement or function, because they arise while working out its values or while the program runs. The error tables of each entry sum them up in the (common) row.

Report When
C Nonsense in BASIC The line is not valid BASIC, or it mixes numbers and strings where it cannot (LET a="x", "a"+1). Nearly always the editor says so when you type the line, and does not store it; the entries say when it comes up while running.
2 Variable not found A variable with no value is used, or an array before its DIM.
3 Subscript wrong A subscript or a slice outside the array or the string.
4 Out of memory There is no memory left for a result, or the expression has too many brackets or FN one inside another.
6 Number too big A result greater than 1.7E38, a division by zero or 0 raised to a negative number.
A Invalid argument A function with a value it does not take: SQR -1, LN 0, ASN 2, the power of a negative number.
B Integer out of range A whole-number argument that is negative or greater than the maximum for its type (see Whole-number arguments).
L BREAK into program You pressed BREAK (Esc) while the program was running, or during a wait (PAUSE, WAIT, BEEP...). CONTINUE carries on from the next statement.

Program flow#

GO TO#

GO TO line
GO TO @label

Jumps to a line and carries on from there. If that line does not exist, it goes to the next one after it; if there is none, the program ends with 0 OK. With a label it jumps to that exact statement, even if it is not the first one on its line. You can also type GOTO, as one word.

Parameters

Parameter Values Meaning
line 0–61439; any expression (GO TO n*100) The line number. Lines go up to 9999: a larger number ends the program.
label a name A @name label in the program.

Errors

Report When
B Integer out of range line is negative or greater than 61439.
X Label not found There is no @label with that name.
(common) See Errors in any statement.

Example

10 PRINT "forever"
20 GO TO 10

Press BREAK (Esc) to stop it.

See also: GO SUB, @label, RUN, ON ERROR.

GO SUB, RETURN#

GO SUB line
GO SUB @label
RETURN

GO SUB jumps to a subroutine, like GO TO, but remembers where it came from; RETURN goes back to the statement after the GO SUB. A subroutine can call others, up to 512 pending GO SUB. You can also type GOSUB.

Parameters

Parameter Values Meaning
line 0–61439 As in GO TO.
label a name A @name label in the program.

Errors

Report When
B Integer out of range line is negative or greater than 61439.
X Label not found There is no @label with that name.
4 Out of memory There are already 512 GO SUB without their RETURN.
7 RETURN without GOSUB RETURN with no pending GO SUB to go back to.
N Statement lost The line RETURN goes back to no longer has that statement (the program was changed with the GO SUB pending).
(common) See Errors in any statement.

Example

10 GO SUB 100: GO SUB 100
20 STOP
100 PRINT "in the subroutine"
110 RETURN

See also: DEF PROC, which is usually clearer; GO TO, @label.

IF, THEN, ELSE#

IF condition THEN statements
IF condition THEN statements ELSE statements

IF condition THEN
  lines
ELSE IF condition THEN
  lines
ELSE
  lines
END IF

If the condition is true (not 0), the statements after THEN run. If it is false, they are skipped: the program carries on at the statements after ELSE, if there is one on the same line, or at the next line.

Parameters

Parameter Values Meaning
condition a number True if it is not 0 (see True and false). A string is an error.
statements statements separated by : What runs. A statement must follow THEN: a number on its own (IF a THEN 100) is an error; write IF a THEN GO TO 100.

Everything after THEN up to ELSE is the true part, and everything after ELSE up to the end of the line, the false part. With several IF on one line, each ELSE goes with the nearest IF.

The block IF. If THEN is the last thing on the line, the IF opens a block of several lines, which ends at END IF. Inside it there can be ELSE IF condition THEN parts (also at the end of their line), tried in order if nothing before was true, and an ELSE part for when none is. Only one part runs; then the program carries on after END IF.

  • ELSE, ELSE IF and END IF start their line. ELSE can be followed by statements on the same line (ELSE PRINT "Adult"), and END IF by others separated by :. An ELSE that does not start the line belongs to a one-line IF.
  • Blocks can go one inside another, with no limit, and contain one-line IFs, loops or GO SUB. You can leave a block with GO TO.
  • It only works in a program: as a direct command, IF a THEN does nothing.

Errors

Report When
C Nonsense in BASIC When typing the line: the condition is a string, THEN is missing, a number follows THEN, or an ELSE IF ... THEN does not end the line.
Y Structure error A block is missing its END IF. It comes up when it has to be looked for: when skipping a part that is not true, or at the end of the one that was.
(common) See Errors in any statement.

Example

10 LET n=-5
20 IF n<0 THEN PRINT "negative" ELSE PRINT "zero or positive"
30 IF n<0 THEN PRINT "a": PRINT "b" ELSE PRINT "c": PRINT "d"

Line 30 prints a and b. With a block:

10 INPUT "Age? ";a
20 IF a<13 THEN
30 PRINT "Child"
40 ELSE IF a<18 THEN
50 PRINT "Teenager"
60 ELSE
70 PRINT "Adult"
80 IF a>=65 THEN PRINT "Retired"
90 END IF

See also: SELECT CASE, WHILE, Expressions, True and false.

SELECT CASE#

SELECT CASE value
CASE values
  lines
CASE ELSE
  lines
END SELECT

Chooses a part by value: the part of the first CASE that matches runs (or the CASE ELSE part if none does), and the program carries on after END SELECT. If none matches and there is no CASE ELSE, nothing runs.

Parameters

Parameter Values Meaning
value a number or a string What is compared with each CASE.
values a list separated by commas (table) Matches if any in the list matches. All of them must be of the type of value.
Value Matches if
5, "yes", a+1 value is equal
1 TO 9, "a" TO "m" value is between the two (both included)
< 0, >= 100, <> 7, = 3 value passes the comparison
  • The CASE are tried in order, and CASE ELSE is taken as soon as it is reached: put it last, because the CASE after it are never tried.
  • Numbers are compared with their full precision, not that of =: SELECT CASE 0.1*3 does not match CASE 0.3. For values with decimals, use ranges (CASE 0.29 TO 0.31).
  • CASE can go on its own line or after :, and the statements of each part on the same line or the following ones; it can all even go on one line, also as a direct command. SELECT CASE can go one inside another.

Errors

Report When
C Nonsense in BASIC A value of a CASE is not of the type of value (it comes up when comparing it), or the values of a CASE are followed by something that is not : or the end of the line.
Y Structure error END SELECT is missing.
(common) See Errors in any statement.

Example

10 INPUT "A key? ";k$
20 SELECT CASE k$
30 CASE "q", "Q": PRINT "Up"
40 CASE "a", "A": PRINT "Down"
50 CASE "0" TO "9"
60 PRINT "A digit"
70 CASE ELSE: PRINT "Something else"
80 END SELECT

On one line: SELECT CASE n: CASE 1: PRINT "one": CASE ELSE: PRINT "other": END SELECT.

See also: IF.

FOR, NEXT#

FOR var = first TO last [STEP step]
NEXT var

Repeats the statements between FOR and NEXT, with the variable going from first to last, adding step each time. With a negative step it counts down; with STEP 0, it never ends. If the loop should not run at all (FOR i=1 TO 0), the program jumps to after the first NEXT of that variable further on.

Parameters

Parameter Values Meaning
var a letter The control variable, numeric. If there was already a variable with that name, it replaces it.
first, last numbers The first value and the last one.
step a number; 1 if omitted What is added on each turn.

After the loop the variable keeps the first value past the end (in the example, 0). NEXT compares with the precision of =, so FOR x=0 TO 1 STEP 0.1 reaches 1.

Errors

Report When
I FOR without NEXT The loop does not run at all and there is no NEXT of that variable further on.
1 NEXT without FOR The variable of NEXT exists, but is not that of a FOR.
2 Variable not found There is no variable with the name of NEXT.
6 Number too big When adding the step, the variable goes past 1.7E38.
C Nonsense in BASIC When typing the line: var is not a single letter, or it is a string.
(common) See Errors in any statement.

Example

10 FOR i=1 TO 10 STEP 3: PRINT i;" ";: NEXT i
20 PRINT
30 FOR i=3 TO 1 STEP -1: PRINT i: NEXT i

See also: WHILE, REPEAT.

WHILE, WEND#

WHILE condition
WEND

Repeats the statements between WHILE and WEND while the condition is true. The condition is checked at the start, so if it is false the first time, the loop is skipped entirely. Loops can be nested: WHILE, REPEAT and procedures, up to 64 one inside another.

Parameters

Parameter Values Meaning
condition a number True if it is not 0.

Errors

Report When
Y Structure error WEND without its WHILE, or the condition is false and there is no WEND further on.
4 Out of memory More than 64 loops and procedures one inside another.
(common) See Errors in any statement.

Example

10 LET n=1
20 WHILE n<100: LET n=n*2: WEND
30 PRINT n

shows 128.

See also: REPEAT, FOR.

REPEAT, UNTIL#

REPEAT
UNTIL condition

Repeats the statements between REPEAT and UNTIL until the condition is true. The condition is checked at the end, so the loop runs at least once.

Parameters

Parameter Values Meaning
condition a number The loop ends when it is not 0.

Errors

Report When
Y Structure error UNTIL without its REPEAT.
4 Out of memory More than 64 loops and procedures one inside another.
(common) See Errors in any statement.

Example

10 REPEAT
20 LET d=INT (RND*6)+1: PRINT d
30 UNTIL d=6

See also: WHILE, FOR.

DEF PROC, PROC, END PROC#

DEF PROC name [(param [, param]...)]
END PROC
PROC name [(value [, value]...)]

A procedure is a named piece of program. DEF PROC starts it and END PROC ends it; PROC runs it and then comes back to the next statement. The parameters receive the values given in PROC and are local: at END PROC they get back the value they had before (or stop existing, if they did not exist). A procedure can call itself.

When the program reaches a DEF PROC while running normally, it skips the whole procedure, so procedures can go anywhere. A procedure does not return a value: to give a result back, store it in a variable.

Parameters

Parameter Values Meaning
name like a numeric variable name The name of the procedure: letters and digits, case and spaces ignored.
param up to 16 A numeric variable name, or a letter with $ for a string.
value up to 16, one per parameter A number or a string, of the type of its parameter.

END PROC also closes any WHILE and REPEAT left open inside the procedure.

Errors

Report When
Z PROC not found There is no DEF PROC with that name.
Q Parameter error The number or the type of the values of PROC do not match the parameters, or there are more than 16.
Y Structure error END PROC outside a procedure, or the program reaches a DEF PROC that has no END PROC before the next DEF PROC.
4 Out of memory More than 64 loops and procedures one inside another, or there is no room for more saved values of parameters and local variables (8 KB for all of them).
(common) See Errors in any statement.

Example

10 PROC greet("Ann", 2)
20 PROC greet("Bob", 1)
30 STOP
100 DEF PROC greet(n$, times)
110 FOR i=1 TO times: PRINT "Hello, "; n$: NEXT i
120 END PROC

See also: LOCAL, GO SUB.

LOCAL#

LOCAL var [, var]...

Inside a procedure, makes those variables local: they start as 0 (or "") and get their old values back at END PROC.

Parameters

Parameter Values Meaning
var up to 16 names Numeric variables (any name) or string variables (a$). Not arrays.

Errors

Report When
Y Structure error LOCAL outside a procedure.
Q Parameter error More than 16 names in one LOCAL.
4 Out of memory There is no room for more saved values of parameters and local variables (8 KB for all of them).
(common) See Errors in any statement.

Example

10 LET i=99: PROC count: PRINT "i is still "; i
20 STOP
100 DEF PROC count
110 LOCAL i
120 FOR i=1 TO 3: PRINT i: NEXT i
130 END PROC

See also: DEF PROC.

@label#

@name

A statement made of @ and a name marks a place in the program, and does nothing else. GO TO, GO SUB, RUN, RESTORE and ON ERROR GO TO can jump to it by name instead of by line number. GO TO, GO SUB, RUN and ON ERROR GO TO go to the exact statement (it does not need to be the first one on its line); RESTORE, to the start of its line. Labels do not change when you renumber. If two labels have the same name, the first one counts.

Parameters

Parameter Values Meaning
name like a numeric variable name Letters and digits, case and spaces ignored.

Errors

Report When
X Label not found (In the statement that jumps.) There is no label with that name.
C Nonsense in BASIC When typing the line: @ is not followed by a valid name.

Example

10 GO SUB @hello: GO SUB @hello
20 STOP
30 @hello: PRINT "hello": RETURN

See also: GO TO, RESTORE, RENUM.

RUN#

RUN [line | @label]

Runs the program from the beginning, or from that line or label. Before starting it stops the music and the sound effects and clears everything like CLEAR: deletes the variables and clears the screen, closes open files, turns off ON ERROR, CLIP and PATTERN, and makes READ start from the first DATA. It does not change the video mode, the colours, TRACE or the stored sprites. To start without losing the variables, use GO TO.

Parameters

Parameter Values Meaning
line 0–65535; 0 if omitted Where it starts. If it does not exist, at the next one there is; if there is none, nothing runs (0 OK).
label a name A @name label in the program.

Errors

Report When
B Integer out of range line is negative or greater than 65535.
X Label not found There is no @label with that name.
(common) And those of the program it runs. See Errors in any statement.

Example

RUN 100

See also: CONTINUE, STOP, CLEAR, GO TO.

STOP#

STOP

Stops the program with the report 9 STOP statement. CONTINUE carries on from the next statement. ON ERROR does not catch STOP.

Parameters: none.

Errors

Report When
9 STOP statement Always: it is how it stops.

Example

10 PRINT "one": STOP: PRINT "two"

After 9 STOP statement, 10:2, CONTINUE prints two.

See also: CONTINUE, ON ERROR.

CONTINUE#

CONTINUE

Carries on after a stop: after STOP or BREAK (L), from the next statement; after an error (D BREAK - CONT repeats too), it repeats the statement that failed, which is useful once you have fixed the cause (for example, by giving a missing variable a value).

It only works for programs: after a stop in a direct command, that command is no longer there (the edit line is now the CONTINUE itself), so it gives N Statement lost. (On the Spectrum, the CONTINUE repeated for ever.)

Parameters: none.

Errors

Report When
N Statement lost The stop was in a direct command, or the line where it has to carry on no longer has that statement (it has been changed).
(common) And those of the statement it repeats. See Errors in any statement.

Example

10 PRINT x

RUN gives 2 Variable not found, 10:1; then LET x=5 and CONTINUE print 5.

See also: STOP, ON ERROR, Reports.

TRACE#

TRACE ON
TRACE #stream
TRACE OFF

To follow where a program goes: each time a line starts running (also when it comes back to it with GO TO, NEXT or RETURN), its number is printed in brackets, like [10][20][30]. TRACE OFF turns it off; it can also go inside the program, to follow only one part. NEW turns it off, RUN does not. If the stream is closed, it turns itself off.

Parameters

The screen and printing#

The program screen has an upper part, where PRINT and the drawing commands work, and a lower part of two lines at the very bottom, used by INPUT and by the reports (it grows if needed). In the normal mode, mode 0, the screen has 24 rows of 32 characters (256 × 192 pixels), and PRINT can use rows 0 to 21; in mode 1, 48 rows of 64 characters, and PRINT uses rows 0 to 45. On a page larger than the screen (see MODE), the rows and columns are those of the page.

PRINT and the drawing commands work on the drawing page (see PAGE, SCREEN), which is normally the one on view.

When printing goes past the last row, the screen scrolls up. Each time a screenful has scrolled, it stops and asks scroll?: press N, Space or BREAK to stop the program (D BREAK - CONT repeats), or any other key to go on.

Colours#

Each character cell of the screen has an ink (INK, the colour of the character) and a paper (PAPER, the background). Colours are numbered from 0 to 7, and BRIGHT 1 makes them brighter:

Number Colour With BRIGHT 1
0 black black
1 blue bright blue
2 red bright red
3 magenta bright magenta
4 green bright green
5 cyan bright cyan
6 yellow bright yellow
7 white (light grey) bright white

The sprite and fast graphics commands, RASTER BORDER and REMAP use the 16 colours directly, from 0 to 15: 0–7 are the colours in the table and 8–15 their bright versions (10 is bright red). Colour 8 is black too, and is used as "transparent" in sprites. With PALETTE, each of the 16 can be any colour you like.

On ZX-V, each pixel has its own colour: drawing a pixel only changes the colour of that pixel, never its neighbours.

If you know the Spectrum: there is no colour clash. PLOT, DRAW and CIRCLE paint with the ink only, pixel by pixel; ATTR still reports the last colours written in each cell.

INK, PAPER, FLASH, BRIGHT, INVERSE and OVER can be used in two ways:

  • As statements, they change the colours for everything printed and drawn from then on (permanent colours).
  • As items inside PRINT, INPUT, PLOT, DRAW and CIRCLE, followed by ;, they apply to that statement only (temporary colours).

All of them read their value as a number from 0 to 255: a negative value or one greater than 255 gives B Integer out of range, and one from 0 to 255 that is not one of theirs, K Invalid colour (see Whole-number arguments).

10 PAPER 1: INK 6: CLS
20 PRINT "yellow on blue"
30 PRINT PAPER 2; INK 7; "white on red, only here"
40 PRINT "yellow on blue again"

Drawing with PLOT and DRAW#

These commands draw on the drawing page with the ink colour. Their coordinates are in pixels, with (0, 0) at the bottom left corner: x goes from 0 to 255 to the right and y from 0 to 175 upwards (the two bottom rows belong to the lower part of the screen). In mode 1, x goes to 511 and y to 367; on a page larger than the screen (see MODE), x goes to the width of the page minus 1 and y to its height minus 17.

A point outside the screen gives B Integer out of range. A line or a circle that goes outside gives the report when it reaches the edge: what has been drawn up to there stays. Watch out: PLOT and POINT ignore the sign of the coordinates: PLOT -10,20 draws at (10, 20).

You can put colour items at the start, followed by ;, as in PLOT INK 2; 10,10, which apply to that statement only. Without them, each point only changes the ink of its cell (the one ATTR gives): the paper, brightness and flashing are kept.

PLOT, DRAW and CIRCLE leave the last point drawn as the starting point of the next DRAW. CLEAR and RUN move it to (0, 0).

The fast graphics commands (BOX, SPRITE...) count y from the top instead, like PRINT AT.

Video modes and screen effects#

These commands change how the whole screen looks: its size, the page that is shown, the scrolling and the colours, all without redrawing anything.

Common errors. Numbers are rounded to the nearest integer. A negative one (except the lines of RASTER, which can be), or one greater than the maximum the command accepts (255 in almost all; 65535 for sizes, scrolls and the values of RASTER), gives B Integer out of range before anything else, even if the command then checks a narrower range with another report: PAGE 2 gives A, but PAGE 300 gives B; REMAP 20,1 gives K, but REMAP 300,1 gives B.

MODE#

MODE n, width, height

Chooses the screen mode and clears the screen:

Mode Pixels Text
0 256 × 192 32 columns × 24 rows (the one at start)
1 512 × 384 64 columns × 48 rows

MODE clears both pages, shows page 0 and draws on it (like PAGE 0 and SCREEN 0), and removes scrolling, REMAP, PALETTE, RASTER and CLIP. The sprites, the tiles and the rest of the graphics store are kept, and so is the PATTERN pattern.

In mode 0, the page can also be larger than the screen, so that the screen is a window that you move over it with SCROLL: MODE 0, 512, 384, MODE 0, 1024, 192 or MODE 0, 256, 768. Then PRINT AT, PLOT and the rest cover the whole page (PRINT AT reaches column 127 on a 1024-pixel-wide page).

Shows one colour as another everywhere on the screen, instantly and without redrawing: after REMAP 1,10, everything blue is shown bright red. This is useful for fades, flashing and colour cycling.

There are three remap tables, 0 to 2. Without #, REMAP changes table 0, which is the one normally in use. REMAP #t; ... changes table t without showing it; REMAP #t makes the whole screen use table t (so all its changes appear at once); RASTER REMAP uses a table for some lines only. REMAP alone resets the three tables and goes back to table 0. So does MODE.

REMAP swaps one of the 16 colours for another; what each colour looks like is set by PALETTE.

Parameter Values What it is

Errors

Report When

K Invalid colour colour or newcolour is between 16 and 255.
B Integer out of range table, colour or newcolour is negative or greater than 255.

PALETTE#

PALETTE

Changes how one of the 16 colours looks: r, g and b are its red, green and blue. Everything drawn in that colour changes instantly. After PALETTE 1, 255, 128, 0, blue is shown orange.

The usual colours have 215 in each component (255 the bright ones): red is PALETTE 2, 215, 0, 0. The screen has 65,536 possible colours, and the nearest one is used.

Each REMAP table has its own palette. Without #, PALETTE changes table 0's, the one normally in use; PALETTE #t; ... changes table t's. So, with RASTER REMAP, each band of the screen can have its own 16 colours. PALETTE #t alone gives table t back its usual colours, and PALETTE alone does it for all three (without changing the table in use). MODE also resets them.

Colour 8 is still transparent in sprites and in the map cells that ask for it (it is not drawn), even if the palette gives it another colour.

Parameters

Parameter Values What it is
table 0–2 The table whose palette changes. Without #, table 0.
colour 0–15 The colour that changes.
r, g, b 0–255 Its red, green and blue.

Errors

Report When
A Invalid argument table is between 3 and 255.
K Invalid colour colour is between 16 and 255.
B Integer out of range table, colour, r, g or b is negative or greater than 255.

Example

See also: REMAP, RASTER, colour table.

Sprites, tile maps and fast graphics#

These commands use the ROM's graphics engine to draw games quickly: sprites with transparency, scrolling tile maps, perspective floors and rotating backgrounds ("mode 7") and filled shapes, plain or patterned. They differ from PLOT and DRAW in a few ways:

  • Coordinates are in pixels from the top left corner of the page, with y going down, like PRINT AT. They go from −32768 to 32767, and can be negative or off the page: whatever falls outside is simply not drawn.
  • Colours are the 16 colours by number, 0 to 15 (see the colour table). In sprites, colour 8 is transparent; in maps, only in the cells that ask for it (see MAP POKE).
  • They draw on the drawing page chosen with SCREEN. For smooth animation, draw on the hidden page, show it with PAGE and wait with WAIT.
  • POINT, ATTR and SCREEN$ do not see what they draw; PIXEL does. A cell with FLASH stops flashing when one of these commands draws over it.

Sprites, tiles, maps and textures are kept by number in a graphics store in memory. They survive RUN, CLEAR and LOAD (so a loader can prepare the graphics and then load the game), and NEW deletes them. Defining a number again replaces it. SAVE "name" GRAPHICS saves the whole store in a .gfx file, and LOAD "name" GRAPHICS loads one (see SAVE and LOAD). You can also draw them on the PC with the graphics editor zxv-gfx, which comes with the emulator, or on the machine itself with LOAD "ROM:gfxedit", or make .gfx files from PNG images with the SDK tool png2gfx (see the SDK graphics guide).

Store Numbers
Sprites 0–255
Tiles 0–4095 in each of the two sets (8 × 8 and 16 × 16)
Maps 0–15
Textures 0–3

GRAB#

  • The second form takes the pixels from a string, one character per pixel, row after row, width pixels per row: the hexadecimal digits 0–9 and a–f (or A–F) are colours 0 to 15, and any other character (., a space...) is transparent, as is 8. TILE#

MAP DIM, MAP POKE#

MAP DIM creates tile map m with width × height cells, all set to tile 0. With wrap = 1 the map repeats endlessly in both directions. It takes 2 bytes per cell.

MAP POKE sets the cell at column x, row y (counting from 0). The value is the tile number plus any of these:

Add Effect
4096 tile mirrored left to right
8192 tile upside down
16384 colour 8 of the tile is transparent (lets what is behind show); without this, colour 8 is drawn as just another colour (black, with the usual palette)
32768 priority (see the filter of MAP)

With a string, it fills the cells from x to the right, using the code of each character as the tile number: " ##.." uses tiles 32, 35 and 46. This makes it easy to draw levels with text. Whatever goes past the right edge of the map is not set.

value 0–65535 The tile (0–4095) plus the additions of the table.

FLOOR#

Draws a floor in perspective with texture n or, with MAP, with tile map m (as the SNES did: a whole race track fits in a map), as seen from point x, y of the texture or map at that height, looking in direction angle. PLAY#

PLAY a$ [, b$]...

Plays music written as text, with up to six voices at once: the first three strings play on channels A, B and C of the first AY chip, and the next three on those of the second. Up to eight strings can be given, as on the 128K (there the seventh and eighth were for MIDI): the seventh and eighth are checked, but do not sound.

The program waits until all of them have finished; BREAK stops them. All the strings are checked before any sound starts. PLAY stops the MUSIC music, which uses the chips its own way; the SFX effects carry on.

Inside each string (the commands in upper or lower case):

Text Meaning
c d e f g a b a note (C, D, E, F, G, A, B); upper case C...B is one octave higher
#, $ sharp or flat (before the note): #f, $b
& a rest (silence)
1 to 9 length of the following notes: 1 semiquaver (sixteenth note), 2 dotted semiquaver, 3 quaver (eighth note), 4 dotted quaver, 5 crotchet (quarter note, the default), 6 dotted crotchet, 7 minim (half note), 8 dotted minim, 9 semibreve (whole note)
10 11 12 triplets of semiquavers, quavers and crotchets: they apply to the next three notes
n_m tied lengths: the next note lasts both (more can be tied: 5_5_3)
O n octave, 0 to 8 (default 5, where c is middle C)
T n tempo in crotchets per minute, 60 to 240 (default 120); only counts in the first string
V n volume, 0 to 15 (default 15); stops using the envelope
U use the volume envelope
W n envelope shape, 0 to 7
X n envelope period, 0 to 65535
M n mixer, 0 to 63: bits 0–2 turn on the tone of channels A, B and C, bits 3–5 their noise
N separator (does nothing)
( ) repeat what is inside once (up to 4 levels); a ) without its ( repeats the whole string for ever (until BREAK)
!...! a comment
H stop all voices and end the PLAY
Y n, Z n MIDI on the 128K: checked (Y up to 16, Z up to 255) and ignored

Spaces are ignored. The envelope and mixer belong to each chip, so they are shared by its three voices. Each PLAY starts with the tempo at 120 and the mixer with the tone of its voices on and the noise off.

SOUND#

SOUND register, value [; register, value]...

Writes directly to the registers of the AY chips and of the sample channels, for sound effects. Registers 0 to 15 belong to the first chip and 16 to 31 to the second (same meaning, 16 higher). What SOUND writes on the music's chip lasts until the music writes that register again.

Register Use
0–1, 2–3, 4–5 tone period of channels A, B and C (low byte, high byte 0–15); the frequency is 110 840 / period Hz
6 noise period, 0–31
7 mixer: a bit at 0 turns on: bits 0–2 tone A, B, C; bits 3–5 noise A, B, C
8, 9, 10 volume of A, B and C, 0–15; 16 uses the envelope
11–12 envelope period (low, high)
13 envelope shape (writing it restarts the envelope)

Registers 64 to 159 are those of the twelve sample channels, eight per channel: channel c (0–11) starts at 64 + 8 × c. To play recorded sounds SAMPLE is easier; the details are in the sample channels of the SDK reference.

Register Use
64 + 8 × c the sample: an entry of the sample table, 0–255 (the SAMPLE ones are 224 to 255)
+ 1 the volume, 0–64
+ 2 the pan: 0 left, 128 centre, 255 right
+ 3 the control: 1 starts it, 2 stops it (4, without interpolation; 8, direct mode)
+ 4, + 5, + 6 the step, from low byte to high (8.16: 65,536 is 48 kHz)
+ 7 where it starts, in steps of 256 samples

Parameters

Parameter Values What it is
register 0–31 and 64–159 The register.
value 0–255 What is written.

Errors

Report When

MUSIC#

LOAD name$ MUSIC
MUSIC PLAY
MUSIC STOP
MUSIC PAUSE
MUSIC CONTINUE
MUSIC                          (function)

Plays music made with a tracker, in the background: the program carries on while it plays, as in games.

LOAD name$ MUSIC loads a module. Without an extension, the first there is of name.zxm, name.pt3, name.mod, name.s3m, name.xm, name.vgm and name.vgz; if there is none, the error is the one for not finding name.pt3. It can be:

  • ZX-V's own format (.zxm, with both AY chips and the sample channels: the one zxv-tracker or zxv-music saves);
  • a MOD, an S3M (Scream Tracker 3) or an XM (FastTracker 2), which it converts when loading and which play on the sample channels (up to 12: of those with more, the 12 that play the most notes);
  • Pro Tracker 3 or Vortex Tracker II (.pt3, which zxv-tracker also saves), a TurboSound (two modules, one on each AY chip: six voices), Pro Tracker 2, Sound Tracker, ASC Sound Master or a PSG dump;
  • a VGM (.vgm, or compressed, .vgz: the registers of the AY chips, as emulators record them; see VGM).

The samples of a MOD, an S3M, an XM or a .zxm go from the file to the sound memory (96 KB) when it is loaded, and only the song stays in the BASIC's memory (repeated patterns, once): the file can be bigger than that memory (a 300 KB MOD or a 1.6 MB XM fit, for example). With more than 96 KB of samples, the biggest ones go in ADPCM, and if they still do not fit, also at half the rate (with less treble): modules with up to about 96 KB of samples sound best, and almost the same up to about 170 KB.

  • MUSIC PLAY plays it from the start and, at the end, goes back to the module's loop position, for ever.
  • MUSIC STOP stops it; MUSIC PAUSE silences it and MUSIC CONTINUE carries on where it was.
  • The MUSIC function is 1 while it plays and 0 if not (also when paused).

A .zxm with sample tracks plays them on the sample channels from 0 on (one per track; the rest stay free), and when it starts it uploads its samples to the beginning of the sound memory and of its table.

An AY module plays on the first chip (a TurboSound or a VGM for two AY chips, on both); a MOD, an S3M or an XM, on the sample channels; and a .zxm, on the chips and sample channels its tracks use. It is played by the same code as the tracker and C programs. It stops with MUSIC STOP, BREAK, RUN, NEW, PLAY (which uses the chips its own way), when another module is loaded and when a native program is loaded; if the program ends or gives an error, it keeps playing. What SOUND writes on the music's chip lasts until the music writes that register again.

In the BASIC's memory, an AY module or a VGM takes the size of its file (2 to 15 KB for a normal PT3; a .vgz also takes 32 KB to decompress it while it plays), and a MOD, an S3M, an XM or a .zxm only its song: its samples go to the sound memory. The module goes with the graphics: RUN and CLEAR keep it and NEW deletes it.

Parameters

Parameter Values What it is
name$ file name The module, with or without an extension.

Returns (the MUSIC function): 1 while the music plays; 0 if it is stopped, paused or there is none.

Errors

Report When
A Invalid argument MUSIC PLAY without a module loaded.
C Nonsense in BASIC MUSIC as a command without PLAY, STOP, PAUSE or CONTINUE; SAVE, VERIFY or MERGE with MUSIC.

SAMPLE#

LOAD name$ SAMPLE n
SAMPLE n [, pitch [, volume [, pan]]] [; channel]
SAMPLE STOP [channel]
SAMPLE                         (function)

Recorded sounds (hits, voices, instruments) on the twelve sample channels, without waiting, together with the music and everything else.

  • LOAD name$ SAMPLE n loads a WAV (without an extension, name.wav) into sample n: 8- or 16-bit PCM, mono or stereo (mixed down), at any rate up to 1 MHz. It goes to the sound memory (96 KB) in 8 bits; it takes nothing from the BASIC's memory. If the WAV has a loop (the one Audacity and sound editors save), the sample repeats it until it is stopped. Loading a sample stops those that are playing.
  • SAMPLE n plays it at its own pitch, at full volume and in the centre.
  • Without ; channel, it plays on a channel the music does not use (if there is none left, on the one that has had a sample the longest). With ; channel, on that one: if it is a music channel, it covers the music while it plays, and the music carries on there at its next note.
  • SAMPLE STOP stops them all; with channel, the one on that channel.
  • The SAMPLE function is 1 while any of them plays.

With the music: the song's samples go into the sound memory from the bottom and the SAMPLE ones from the top. Load the SAMPLE ones first: a song loaded afterwards fits into the room left (in ADPCM, or with less treble if need be), and a sample loaded after a song only uses what the song leaves free. A .zxm is already converted and doesn't adjust: if it doesn't fit, 4 Out of memory; make it with zxv-music --free so that it leaves room. BREAK, RUN and NEW stop the samples; the loaded ones are kept like the SFX bank, and NEW clears them.

Keyboard, joystick and mouse#

INPUT#

INPUT [items] variable [, variable]...
INPUT [items] LINE a$
INPUT #stream; variable [, variable]...

Stops the program and lets the user type values into variables, in the lower part of the screen. The items are as in PRINT: string literals and expressions in brackets are shown as a prompt, AT, TAB and colours work, and each variable waits for a value.

  • For a number, the user types a number or a numeric expression (even 2*3), then Enter. If it has a syntax error, a ? marks where, so the user can correct it. If it is correct but fails when worked out (a variable that does not exist, 1/0), the program stops with that report.
  • For a string, the input starts with a pair of quotes and the cursor inside them, because what the user types is taken as a string expression.
  • LINE a$ takes the text exactly as typed, with no quotes.
  • Pressing Esc (BREAK), or typing STOP as the value, stops the program with H STOP in INPUT.

While typing, the left and right cursor keys, Home, End, Backspace and Delete work. The cursor shows L, or C when Caps Lock is on. Whatever was pressed earlier for INKEY$, IN or KEY does not appear: the input starts empty.

The program's texts cannot hold accented letters, ñ or ¿, and neither can what is typed in the INPUT: letters lose their accent, so Peña arrives as Pena (see Character set).

With #stream it reads from a file, one line per variable (see Reading and writing text files).

variable a numeric or string variable, or an array element Where what is typed is stored.
LINE a$ a string variable Takes the text as it is, without quotes.
stream 0–15 The stream it reads from (see Streams and channels).

INKEY$#

INKEY$
INKEY$ #stream

A function: the key being pressed at this moment, as a one-character string, or "" if there is none (or more than two at once). It does not wait. It reads the keyboard like the Spectrum's:

  • Letters come out in lower case (upper case with Shift or Caps Lock), digits as digits and Enter as CHR$ 13.
  • The cursor keys give CHR$ 8 (left), CHR$ 9 (right), CHR$ 10 (down) and CHR$ 11 (up), and Backspace, CHR$ 12.
  • Shift works as the Spectrum's CAPS SHIFT and Ctrl as its SYMBOL SHIFT: punctuation comes out as the keyboard gives it (,, "...), and Ctrl with a letter gives the same as SYMBOL SHIFT with it on the Spectrum, which is sometimes a keyword (Ctrl+A gives CHR$ 226, STOP).
  • A joystick set up as keys with JOY also counts.

Whatever is pressed while a program reads the keyboard this way (with INKEY$, IN or KEY) is not kept for later: when the program ends it does not appear typed in the editor, and an INPUT starts empty.

Files and the SD card#

Programs and data are kept on the SD card. There is also a read-only drive, ROM:, with the examples that come with the machine, and the external drive, EXT:: a folder served by another device (through the board's J5 header, or in the emulator with --ext), which is read and written like the card (see The EXT: drive).

Errors from the card (or from ROM: or EXT:) come from the firmware, and BASIC turns them into reports: a file that does not exist gives T, a name that is not valid gives F, no card gives U, too many open files give O, and anything else gives V Disk error, which adds the reason when it is known.

Common errors. Besides those of each statement, any file statement can give:

Report When
F Invalid file name The name is empty, over 255 characters or has a control character; a part of the path is over 63 characters, has \ : * ? " < > \| or ends in a space or a dot; or there are wildcards where they are not allowed.
T File not found A folder of the path does not exist, or the file where it must exist.
U No SD card The path goes to the card and there is none in the slot (or it has been taken out).
O Invalid stream There are already 8 files open on that drive (with OPEN #) and another one has to be opened.
V Disk error The card failed to read or write, or its format is not understood (with no reason after it).
V Disk error (not a folder) A part of the path that should be a folder is a file.
V Disk error (no server for EXT:) The path goes to EXT: and there is no server, or it has stopped answering.

Statements that write also give V Disk error (not allowed) on ROM:, and V Disk error (card full) if there is no room left.

File names and drives#

  • A name has up to 63 characters, without \ : * ? " < > |, without accented letters or ñ, and does not end in a space or a dot. Upper and lower case are the same. A whole path has up to 255 characters.
  • Folders are separated with /. A path starting with / begins at the root of the drive; otherwise it starts in the current folder (see CD). .. is the folder above (at the root, it stays there) and ., the same one.
  • ROM:, SD: and EXT: at the start (in capitals or not) choose a drive, from its root: LOAD "ROM:hello", CAT "SD:/games", SAVE "EXT:copy". Without a drive, the drive of the current folder is used. Writing to ROM: (SAVE, ERASE, MKDIR...) gives V Disk error (not allowed). With no server connected, everything on EXT: gives V Disk error (no server for EXT:).
  • Wildcards in CAT, ERASE, MOVE and COPY: * stands for any group of characters (also none) and ? for one, with upper and lower case the same, in the last part of the path only: "*.zvb", "games/level?.dat". A wildcard in a folder of the path gives F Invalid file name. If nothing matches, ERASE, MOVE and COPY give T File not found; CAT lists nothing.
  • A file that is open (with OPEN #) cannot be opened again for writing, deleted or renamed: V Disk error (not allowed).

SAVE#

SAVE name$ [LINE line [SCREEN$] [PROTECT]]
SAVE name$ CODE start, length
SAVE name$ SCREEN$
SAVE name$ DATA letter()
SAVE name$ DATA letter$()
SAVE name$ GRAPHICS

Saves to the SD card (or to EXT:). An existing file is replaced.

  • The program (with no other words) and its variables, in a .zvb file, the format of ZX-V programs: both as they are in memory, with no limit but the memory. With LINE, the program starts by itself from that line when loaded, with its variables. With LINE and SCREEN$, it also carries the screen you see as a loading screen: LOAD puts it up first, and the program starts with it. With PROTECT at the end, it is saved protected (see Protected programs).
  • CODE: length bytes of memory from address start, in a .bin file (just the bytes). The addresses are those of PEEK: below 65536, the virtual Spectrum.
  • SCREEN$: the program's screen, as you see it (its mode, its border and the colour of each pixel; if they are not the usual colours, also the colours it is shown with, see PALETTE), in a .gfx file with a screen (which you can edit in zxv-gfx). With the extension .scr, the Spectrum's one (CODE 16384,6912: the ink and paper shadow of each cell, without what is drawn with ZX-V's colours), in the format of its tools.
  • DATA: an array (numbers or characters), in a .zvd file, the format of ZX-V data: as it is in memory, with no limit but the memory.
  • GRAPHICS: the graphics store (sprites, tiles, maps, textures) as a .gfx file.

If the name has no extension, each kind gets its own: .zvb, .bin, .zvd or .gfx (GRAPHICS and SCREEN$). With another extension, CODE is saved the same way, as plain bytes, and a program, an array or a screen in its format.

With the extension .tap, it is saved as a Spectrum tape, to take it to a Spectrum emulator: the program and its variables, the CODE block (with its address, so that LOAD puts it back), the screen (the Spectrum's, as with .scr) or the array, in the Spectrum's format. The loading screen and the protection only go in a .zvb. ZX-V's own keywords show there as odd characters, and a block cannot be over 65535 bytes, nor a string over 65535 characters. A .tzx is not saved.

With the extension .bas, the program is saved as a listing in plain text (see Listings in text): SAVE "game.bas". A listing has neither the variables nor the start line.

start 0–4294967295 The first address of CODE.
length 0–4294967295 (up to 65535 in a .tap) How many bytes.
letter a letter The array for DATA: a() of numbers, a$() of characters.

LOAD#

LOAD name$
LOAD name$ CODE [start [, length]]
LOAD name$ SCREEN$
LOAD name$ DATA letter()
LOAD name$ DATA letter$()
LOAD name$ GRAPHICS
LOAD name$ MUSIC
LOAD name$ SFX
LOAD name$ SAMPLE n

Loads from the SD card (or from ROM: or EXT:):

  • A program: replaces the program in memory, and its variables replace the ones there were. If it was saved with LINE, it runs from that line without clearing them, as with GO TO. Without an extension, ZX-V tries name.zvb, then name.tap, then name.zxv (a native program, which runs), then name.bas (a listing in text) and finally the name as it is. Spectrum .tap and .tzx files with BASIC programs load directly, with their variables (see Tape files); ZX-V .tap files from before 0.7 carry no variables. The old program is deleted before the new one is read (so one as big as the memory fits): if the file turns out not to be valid, memory is left with no program and no variables, but the editor's Undo option brings the lines back.
  • CODE: a file of bytes (without an extension, name.bin and then name.tap), at start and at most length bytes (without length, the whole file). A file that is not a .tap does not know where it goes, so start is needed: LOAD "data" CODE 40000; the CODE block of a .tap goes back without it to the address it was saved from.
  • SCREEN$: a screen (without an extension, name.gfx and then a block of name.tap). The one in a .gfx goes up as it is, with its mode (if it is not the current one, it changes as with MODE) and its border; if it carries its colours, they go into table 0's palette, without REMAP changes, and that table becomes the one in use (as with REMAP #0). SCREEN$() does not recognise the text on it. A .scr or a .tap is a Spectrum screen, shown as it was.
  • DATA: an array (without an extension, name.zvd and then name.tap), replacing the array of that name, as DIM does. The type must match.
  • GRAPHICS: the objects of a .gfx file (without an extension, it is added) replace those with the same number; the others stay, so you can load sprites from one file and a level from another.
  • MUSIC, SFX and SAMPLE: a music module, an effect bank or a recorded sound (see MUSIC, SFX and SAMPLE). Without an extension, MUSIC tries .zxm, .pt3, .mod, .s3m, .xm, .vgm and .vgz (if there is none, .pt3); SFX adds .afb, and SAMPLE, .wav.

LOAD "" (an empty name) loads the next block from the inserted tape (see Tape files); with GRAPHICS, MUSIC, SFX or SAMPLE the empty name is not allowed.

The program's folder. ZX-V remembers the folder the program was loaded from. A name with no drive and no leading / is looked for in the current folder first and, if it is not there, in the program's folder. So a game loaded with LOAD "ROM:game" finds its graphics and music with LOAD "game" GRAPHICS, without writing ROM:; and a file with the same name in the card's current folder comes first, so you can replace them without touching the game. It also works for VERIFY, MERGE and OPEN # for reading (not for writing: SAVE always goes to the current folder). NEW forgets it.

Protected programs#

SAVE name$ LINE line [SCREEN$] PROTECT

If you do not want the people who play your program to see how it is made, save it with PROTECT. The program in memory does not change: you can go on working on it and also save it unprotected, for yourself.

  • A protected program starts by itself when it is loaded, so it needs LINE. It is only saved in a .zvb (in a .tap or a .bas, C Nonsense in BASIC).
  • While it runs, it is like any other: ON ERROR catches errors and BREAK.
  • When it stops, for any reason (an error, BREAK, STOP or because it ends), its report appears and it is deleted, with its variables, as with NEW. It cannot be listed, the deletion cannot be undone, and the debugger does not connect to it.
  • MERGE does not accept it (R Loading error), and if it saves the program itself, it is saved protected (and needs LINE).
  • If it loads another program, that one is not protected (unless it was saved that way).

It is a protection like the Spectrum's: it stops the curious, but the file format is open, and someone who knows can read it on a PC. ZX-V's tools do not show its listing either.

Listings in text#

A program can also live in a plain text file with the extension .bas, one line of the program per line, each with its number, as LIST shows it. You can write it in any text editor on your computer, copy it to the card and load it with LOAD "game.bas" (or MERGE); SAVE "game.bas" writes the one in memory, with the indentation of LIST.

10 REM Written outside ZX-V
20 for i = 1 to 10: print i: next i
  • Each line is read as if you typed it in the editor: keywords in capitals or not, and the same syntax check. A line with an error stops the loading with its report and its line number (C Nonsense in BASIC, 20:1); the lines before it stay in memory.
  • The number goes at the start (it can have spaces before it) and is from 1 to 9999; otherwise C Nonsense in BASIC (with the number of the last good line). A line with only a number deletes that line, and blank lines are ignored. A .bas file is a program, not a list of commands (leave RUN out).
  • LOAD of a .bas first deletes the program and the variables; MERGE merges it with the one in memory and keeps the variables. Both can be undone (the program lines, not the variables).
  • The text is UTF-8. Accented letters lose the accent, as when you type them (año becomes ano); £ and © are those of the Spectrum, and the block graphics are written with the Unicode quadrant characters (▘ ▝ ▀ ▖ ▌ ▞ ▛ ▗ ▚ ▐ ▜ ▄ ▙ ▟ █). UDG characters are saved as single bytes, which a text editor may show oddly but which load back correctly.
  • Lines can end in LF (Linux, macOS) or CR LF (Windows); a line can be up to 1024 characters long (otherwise G No room for line).
  • A listing carries no variables, no start line and no protection.

Native programs#

Programs written in C with the SDK are .zxv files. LOAD "name" runs them (the extension is optional). A native program uses the memory of BASIC: when it ends, the BASIC program and its variables are gone, so save your BASIC program first. Before loading it, the machine checks the whole file (a damaged or half-copied file is not loaded); then it closes the files open with OPEN #.

LOAD "ROM:hello"

When the program ends, BASIC shows a report, as after a command (ON ERROR does not catch it):

  • 0 OK, 0:1 if it ended normally.
  • W Native code error (3), 0:1 if it ended with an error code (3 in this example), or W followed by the program's own message if it gave one: W Data file damaged (5), 0:1.
  • W Native code error, 0:1 if it crashed (for example, by reading from a forbidden address).
  • None if you stopped it with Ctrl+Alt+Delete: the machine starts again, as when you switch it on.

The report is the native program's: your BASIC program is gone in every case. These can appear before it starts, and then the BASIC program is still in memory:

Report When
R Loading error It is not a valid .zxv, it is for a newer ROM, or it was asked for with VERIFY or MERGE.
4 Out of memory It does not fit in user memory (compiled for another memory, or too big).
(common) See Common errors.

If the card fails, or the file changes, once it is already loading, you get its error (for example, V Disk error) and the BASIC program is gone too.

Tape files#

ZX-V reads the tape files of Spectrum emulators, .tap and .tzx (their standard-speed blocks: programs, CODE, screens and arrays; the other blocks of a .tzx are skipped), to use BASIC code made for the Spectrum. Spectrum machine code inside them cannot run. ZX-V programs are saved in their own format, .zvb (see SAVE); a .tap is only saved when asked for, to take a program to a Spectrum emulator.

A tape file that has been loaded stays inserted, like a cassette in a tape recorder, so programs in several parts work:

  • LOAD "" (also LOAD "" SCREEN$, LOAD "" CODE, LOAD "" DATA a(), VERIFY "", MERGE "") reads the next block of that kind from where the tape stopped. When it reaches the end it rewinds once. With no tape inserted, or no block of that kind, R Loading error.
  • LOAD "name" uses the file name (with the usual extensions) if it exists on the card, and if it is a tape it becomes the inserted tape; if it does not exist, it looks on the inserted tape for a block with that name (up to 10 characters, with upper and lower case the same), and if it is not there either, T File not found.
  • A damaged block (with a wrong checksum, or cut short) gives R Loading error.
  • The tape stays inserted after NEW and CD, until another tape file is loaded or the machine is reset.

So LOAD "game" loads the loader from game.tap, which can then bring its title screen and the main program with LOAD "" SCREEN$: LOAD "".

When a .tap is saved, the block name is the file name without the folder or the extension, its first 10 characters: SAVE "games/ship.tap" is called ship, as on the Spectrum.

Streams and channels#

Text goes in and out through numbered streams, 0 to 15. Streams 0 to 3 are ready from the start:

Stream Goes to
0, 1 the lower part of the screen (channel "k")
2 the upper part of the screen (channel "s"), used by PRINT
3 the printer, the file printer.txt on the card (channel "p"), used by LPRINT

PRINT, LIST and INPUT take a stream with #: PRINT #1; "bottom" prints in the lower part and LIST #3 lists to the printer. Streams 4 to 15 can be connected to text files. A stream that is not open gives O Invalid stream.

OPEN, CLOSE#

OPEN #stream, channel$

OPEN # ... OUT creates a text file (emptying it if it exists) to write to; OPEN # ... IN opens one to read (also in the program's folder). Files can only use streams 4 to 15, and each drive has at most 8 files open at once. Opening a stream that already has a file closes it first.

Reading and writing text files#

PRINT #stream; items
LIST #stream [, line]
INPUT #stream; var [, var]... [LINE a$]

  • PRINT #n writes like PRINT, without colours or AT; TAB writes spaces and keywords come out as text. In a file, a comma starts a new line, so that what PRINT #n; a, b$ writes can be read back with INPUT #n; a, b$.   • LIST #n writes the program as text.
  • INPUT #n reads one line for each variable (lines can end in LF, CR or CR LF; of a line over 1024 characters, the rest is lost). A string variable takes the whole line; a number is worked out as an expression. Nothing is written to the file in INPUT #n: prompts are not allowed.

Memory and system#

PEEK, POKE#

PEEK address
POKE address, value

PEEK (a function) reads a byte from memory and POKE writes one.

  • Addresses below 65536 go to a virtual Spectrum memory, so that Spectrum programs that PEEK and POKE the screen, the colours or the system variables still work (see The virtual Spectrum memory). Everything there can be read, and POKE into the ROM (below 16384) does nothing.
  • Addresses from 65536 up read and write the real memory of ZX-V, byte by byte (for example the machine registers). PEEK reads the flash up to the end of the ROM (268435456 to 269221887) and the RAM (536870912 to 537333759); POKE only writes in that RAM. Careful: BASIC and your program are there too, and a wrong POKE can hang the machine.

Parameter Values What it is
address 0–65535 (the virtual Spectrum); 268435456–269221887 (PEEK only) and 536870912–537333759 (the RAM) The byte.
value −255–255 What POKE writes. A negative value is written as 256 plus that value (−1 is 255).

Returns (PEEK): the byte, from 0 to 255.

Errors

Report When
B Integer out of range address is negative, greater than 4294967295, or from 65536 up outside the areas in the table; value outside −255 to 255.

The virtual Spectrum memory#

Addresses Contents
0–16383 Spectrum ROM: reads as 0, except the character set at 15616–16383; POKE does nothing

User-defined graphics (UDG)#

The character codes 144 to 164 are 21 characters, A to U, that you can draw yourself. USR "a" gives the address of the first byte of character A (and so on to USR "u"); each character is 8 bytes, one per row from the top, and each bit is a pixel (1 = ink). At start, and after NEW, they look like the letters A to U. The system variable UDG (23675) says where they start; you can move it elsewhere in virtual memory.

10 FOR i=0 TO 7: READ b: POKE USR "a"+i, b: NEXT i
20 PRINT CHR$ 144; CHR$ 144; CHR$ 144
30 DATA BIN 00111100, BIN 01111110, BIN 11011011, BIN 11111111
40 DATA BIN 11111111, BIN 10111101, BIN 11000011, BIN 01111110

The editor cannot type these characters: use CHR$.

USR#

USR address
USR "letter"

A function. With an address of 65536 or more, calls native RISC-V machine code at that address and gives back the value it returns (in register a0). Spectrum Z80 machine code cannot run: an address below 65536 gives S Z80 code not supported. To call code without using the result, RANDOMIZE USR address (which puts whatever it returns into the RND seed; if that is over 65535, B Integer out of range).

If the native code fails (an illegal instruction, a forbidden address), the program stops with W Native code error; ON ERROR does not catch that report, but the BASIC program stays in memory.

USR "a" to USR "u" give the address of a user-defined graphic.

Error handling#

Reports#

When a program stops, a report appears at the bottom of the program screen:

2 Variable not found, 20:1

It gives a code (a digit or a letter), the message, and where it happened: the line number and the statement within the line (20:1 is the first statement of line 20; line 0 means a direct command). 0 OK means the program ended normally. Press a key to go back to the editor (that key also counts for the editor).

V Disk error adds the reason in brackets if it is known, and W Native code error the number or the message of the native program (see Native programs). The reports appear in the language of the machine (see LANGUAGE). A BREAK also stops the music and the effects.

ON ERROR#

ON ERROR GO TO line
ON ERROR GO TO @label
ON ERROR GO TO 0

From now on, if an error stops the program, it jumps to that line or label instead. There, ERR and ERL say what happened. ON ERROR GO TO 0 turns it off, as do RUN, CLEAR and NEW.

  • The trap turns itself off when it is used, so that an error inside the handler does not loop for ever: write ON ERROR again to keep catching errors.
  • CONTINUE repeats the statement that failed (after BREAK, it goes on with the next one).
  • It catches all errors of a program, BREAK and H STOP in INPUT included, except 9 STOP statement, errors in direct commands, the W of native code that fails with USR and the report of a native program.
  • When it jumps, any FN in progress is forgotten and, if the program was printing on the lower screen, it goes back to the upper one.

Parameters

Parameter Values What it is
line 0–65535 Where it jumps to (if it does not exist, to the next one there is). 0 turns the trap off.
@label a label in the program Where it jumps to.

Errors

Report When
X Label not found There is no such @label in the program.
B Integer out of range line negative or greater than 65535.
C Nonsense in BASIC GO TO is missing.

Example

10 ON ERROR GO TO @oops
20 PRINT 1/0
30 PRINT "carrying on"
40 STOP
50 @oops: PRINT "Error "; ERR; " at line "; ERL
60 ON ERROR GO TO @oops: GO TO 30

See also: ERR, ERL, CONTINUE, Error messages.

Character set#

Each character has a code from 0 to 255 (CODE and CHR$ convert between them):

Codes Characters
0–31 control codes (see below); others print as ?
32–126 letters, digits and symbols, as in ASCII, except 96, which is £
127 ©
128–143 block graphics: the 16 combinations of the four quarters of a character cell
144–164 the user-defined graphics A to U
165–255 the keywords: PRINT CHR$ 245 prints PRINT

Control codes that have an effect when printed:

Code Effect
6 as a comma in PRINT
8 back one column
13 new line
16 to 21 INK, PAPER, FLASH, BRIGHT, INVERSE, OVER: the next character is the value
22 AT: the next two characters are the row and the column
23 TAB: the next two characters are the column (low and high byte)

For example, PRINT CHR$ 22; CHR$ 5; CHR$ 10; "X" is the same as PRINT AT 5,10; "X".

Block graphics. Codes 128 to 143 divide the character cell into four quarters. To find the code of a pattern, add to 128 the values of the quarters filled with ink: 1 top right, 2 top left, 4 bottom right, 8 bottom left. For example, 128 + 2 + 8 = 138 is the left half.

Code Character Code Character Code Character Code Character
128 (empty) 132 ▗ 136 ▖ 140 ▄
129 ▝ 133 ▐ 137 ▞ 141 ▟
130 ▘ 134 ▚ 138 ▌ 142 ▙
131 ▀ 135 ▜ 139 ▛ 143 █

The quarters are in ink and the rest of the cell in paper, as with any other character. The codes are the same as on the Spectrum.

In the editor you can type the codes 32 to 127 (£ and © with their keys, if your keyboard has them; the ` key types nothing). Accented letters, ñ, ¿ and ¡ are not BASIC characters, so the texts of your programs have to do without them. If you type them, in the editor or in an INPUT, a letter with an accent, a diaeresis or a cedilla comes out without it (á as a, Ñ as N, ç as c), ¿ and ¡ come out as ? and !, and any other character does nothing. The ROM does use them in its own messages, such as the error reports in Spanish, but your programs cannot. Block graphics and user-defined graphics are written with CHR$.
